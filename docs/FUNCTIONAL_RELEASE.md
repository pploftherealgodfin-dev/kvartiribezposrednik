# Функционални поправки — 2 октомври 2026

Този release подобрява основните действия при вход, публикуване, търсене и контакт. Запазени са цветовете и всичките 18 снимки с надписи от Readdy v21. Няма промени по схемата, настройките или реалните данни в Supabase и няма добавени production mock данни.

## Поведение

| Действие | Поправка и проверка |
| --- | --- |
| Вход и смяна на акаунт | Закъсняла начална сесия не заменя нов вход. Чужд профил, контакти, лични форми и любими се скриват веднага. Обновяване на токена не изтрива любимите. |
| Любими | Един запис при двоен клик, възстановяване при грешка и явен бутон за повторно зареждане на действителното състояние. Стар отговор не отключва операция на друг акаунт. |
| Търсене | Невалидни числа, повторени параметри и грешни булеви стойности дават обратна връзка. Кварталът и университетът се проверяват в избрания град. Непосочен етаж не се приема за партер. |
| Обяви | Проверки на четирите стъпки, снимка за корица, стойности нула и десетични цени. Двоен клик не публикува втори запис. При вече записана обява и неуспешна снимка посетителят отива към съществуващата обява. |
| Снимки | Повторното свързване е идемпотентно; изгубен отговор се сверява с базата. Без успешно зареден списък управлението е блокирано. Потвърдено изтриване не връща несъществуваща снимка при неуспешно почистване на файла. Изтекъл адрес се обновява веднъж през проверка на достъпа. |
| Контакти | Гостите получават вход с връщане към обявата. Неактивна обява не започва нов контакт. Закъснял отговор не разкрива контакти в друг акаунт. |
| Съобщения | Черновите се пазят отделно за разговорите. Непотвърдено изпращане запазва същия идентификатор при повторен опит. Разговорите се обновяват и без избран получател. |
| Сигнали | Валидирани причина, описание и адрес от платформата; потвърждение само след реален отговор. Резултатът не се пренася в друг акаунт. |
| Контактна форма | Ограничение на чакането, блокирано повторно изпращане, запазен текст при грешка и ново запитване след потвърден успех. Honeypot не показва фалшив успех. |
| Модерация | MFA не отключва панела при грешка. Модераторът вижда потребителите без административни действия. Действията изискват смислена причина и имат защита от двоен клик. |

## Изграждане и SEO

Публичната подготовка и генерирането на HTML вече са част от Vite. И `npm run build`, и директният `npx vite build` трябва да произведат пълните страници в `out`, а не само клиентската обвивка с `noindex`. SSR подготовката се изпълнява в отделен процес и не извлича данни от базата. `public/sitemap.xml` съдържа същия генериран sitemap за стандартното копиране на публични ресурси.

Остават 276 публични HTML страници, 269 Markdown версии и 74 канонични адреса в sitemap, включително 55 градски справочника с достатъчно местни данни. Lastmod продължава да следва действителното съдържание и историята му. Няма измислени задни дати. Динамичните и личните страници остават извън sitemap.

Хостингът трябва да отдава генерирания `out`: статичен HTML преди SPA fallback, SEO файловете с HTTP 200, несъществуващите страници с HTTP 404. GitHub merge сам по себе си не удостоверява правилните HTTP маршрути или завършено публикуване.

## Проверки

`npm run verify` изпълнява TypeScript, lint, 10 UX проверки, 34 функционални React проверки, production build и 9 SEO проверки. GitHub Actions изпълнява същите проверки и отделен директен Vite build при pull request и push към main. Actions използва само изолирани build стойности и не публикува резултата.

Функционалните проверки използват действителните компоненти с изолиран тестов транспорт в `tests/support`; той не се импортва в production. Декодирането на пикселите и canvas са заместени в теста на формата за обява. Покритието на логиката за запис и повторен опит не е доказателство за реално качване на байтове, получен SMS, Google callback или получено контактно запитване.

Трите SQL проверки (`publication_flow.sql`, `access_and_flows.sql`, `photo_integrity.sql`) са изпълнени в новия проект `ygyldkxhgonzbgrfmtmf` с транзакционни fixtures и ROLLBACK. Покриват публикуване в преглед, ограничения на достъпа, филтри, контакти, любими, разговори и снимки. Няма оставени тестови записи или приложени миграции в този release.

## Остава за реалния старт

Реален вход и SMS доставка; качване и преглед на истински снимки; разговор между два отделни акаунта; получаване на контактната форма; определен проверяващ с MFA и реална процедура за проверка на имота. Съществуващата обява в статус „В преглед“ не се публикува автоматично. Наблюдение, резервни копия, възстановяване и натоварване трябва да се проверят в действителната среда. Автоматичните проверки не са гаранция срещу измами или production SLA.
