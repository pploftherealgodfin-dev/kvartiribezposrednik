# Readdy и маршрутизацията

`src/router/index.tsx` запазва първоначалния договор на Readdy: `window.REACT_APP_NAVIGATE` и именувания export `navigatePromise`. При предишната преработка на router-а тези два символа са отпаднали; обикновеният frontend build не проверява този специфичен договор на платформата.

Мостът се регистрира след клиентското монтиране на router-а. Няма достъп до `window` при импортиране или SSR. Promise се разрешава с функция, която използва текущата навигация, за да не остане обвързана със стар маршрут. При демонтиране глобалният handle се премахва, ако все още принадлежи на същия router. Съществуващите ограничения за вход и роли важат и при външна навигация.

Функционалните проверки покриват готовността след монтиране, глобална навигация, query промяна в текущия маршрут, hash/state, replace и history, StrictMode, демонтиране и повторно монтиране, както и гост към лични маршрути. Production build проверява и SSR на публичните страници.

## Синхронизация

Поправката трябва да остане в GitHub main. Readdy Pull извлича main и създава нова Readdy версия; локална AI поправка само в Readdy не се пренася обратно при следващ Pull. Readdy Push заменя цялото съдържание на main, затова не служи като Git merge на по-стара версия с текущите промени.

Документация: [Readdy — GitHub Code Sync](https://docs.readdy.ai/integrations/github).
