# Сигурност, лесно публикуване и бързина — 2 октомври 2026

Редът на работа за първите 100–200 клиента е: защита на достъпа, лесно качване на реална обява, бърз публичен сайт. Запазени са цветовете, 18-те редакционни снимки и надписите от Readdy v21, социалното изображение от v33 и договорът на Readdy router-а. Няма нови production mock данни. Supabase е проверен само чрез четене; няма промени по схема, настройки или записи.

## Сигурност

- Production build и клиентът отказват secret/service_role ключ в публичната конфигурация. Приемането на anon JWT проверява типа на ключа, а не подписа му; Supabase удостоверява заявките и прилага RLS. Google OAuth използва PKCE.
- Всеки генериран HTML, включително SPA fallback, получава CSP преди ресурсите: скриптове само от същия origin, без eval и inline изпълним JavaScript; разрешени са конкретните използвани източници за снимки, API и карта. Referrer policy е `no-referrer`. Inline стиловете остават разрешени за съществуващия интерфейс.
- JPEG/PNG/WebP файловете се проверяват по действителните начални байтове и размери преди декодиране. Отказват се празни, подменени, анимирани и прекалено големи файлове. Пикселите се прекодират до WebP, до 1920 px по дългата страна, без EXIF/GPS метаданните на оригинала.
- При изход, смяна на акаунт или на обява предишното съдържание на детайлната страница се премахва веднага. Черновата също е обвързана с текущия акаунт; закъснели операции не могат да възстановят чужда чернова.
- Премахнати са неизползваните Firebase, Stripe React, Lucide и language detector зависимости. Одитът преди промяната отчете 4 high dependency предупреждения по неизползваната Firebase/gRPC верига; след промяната `npm audit` отчете 0 известни уязвимости. CI проверява одита при всяко изпълнение.

Прегледът на новия проект `ygyldkxhgonzbgrfmtmf` потвърди RLS за всичките 13 public таблици, частни Storage buckets, забранен SELECT за anon върху контакти/профили/съобщения/точни адреси и забранено anon изпълнение на RPC за контакти. Снимките са ограничени до 5 MiB и JPEG/PNG/WebP, доказателствата — до 10 MiB и PDF/JPEG/PNG. Прегледът на метаданни не заменя реални тестове с отделни production акаунти.

Advisor предупреждението за [leaked password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) остава: настройката не е променяна. Текущият интерфейс използва телефонен OTP/Google, а не пароли.

Проверката на изображенията във frontend може да бъде заобиколена чрез директен API клиент; това не е сървърен антивирус. Съществуващите Storage ограничения, RLS и човешкият преглед остават задължителни. Обявите продължават да се записват за преглед, без автоматично одобрение или верификация на имот.

## Публикуване в три стъпки

1. **Жилище:** град, описание и основни условия; квартал, университети, етаж и депозит са по желание.
2. **Снимки:** поне една реална снимка; видим напредък при обработката и избор на корица.
3. **Преглед:** обобщение, връщане за редакция и изрично потвърждение преди изпращане за проверка.

Текстовата чернова се пази в sessionStorage на текущия раздел и е възстановима до 2 часа след последния запис. Снимки и отделни полета за телефон/имейл не се записват там. Изходът, смяната на акаунта и бутонът за изтриване изчистват черновата. Без достъпно локално хранилище формата остава използваема в паметта.

Идентификаторът на опита се пази преди заявката. След потвърден запис се пази и идентификаторът на обявата; грешка при снимките или презареждане насочва към съществуващата обява. След изгубен отговор повторният опит използва същия идентификатор. Двойно натискане е блокирано.

## Бързина

Шрифтовете Onest/Literata и иконите вече са локални WOFF2 ресурси с font-display swap. Използваните 59 икони са в отделен файл от **3 852 bytes**, спрямо **174 156 bytes** за пълния WOFF2. Пълният пакет остава fallback за бъдещи икони. Лицензите са в `public/licenses`. Подмножество се обновява със `scripts/subset-icons.py` и fonttools[woff]; Python не е нужен за build/hosting.

Формата, изборът и управлението на снимките са отделни lazy chunks. Последните обяви на началната страница зареждат код и данни при приближаване към viewport. Главната снимка на обявата остава eager; второстепенните изображения са lazy, с размери и async декодиране. Търсенето на началната страница извлича квартали/университети за избрания град. Зареждането на обяви извлича само използваните квартали, без целия национален каталог.

Измерено върху финалния production output: initial static JS **164 727 gzip bytes**, начална страница с hydration **189 579 gzip bytes**. CI бюджетите са 170 KiB и 205 KiB съответно. Предходният initial JS е 167 474 bytes; основните подобрения са в отложените ресурси, заявките и шрифтовете. Това са размери на файлове, а не измерени production Core Web Vitals.

## Проверки и публикуване

`npm run verify` премина: TypeScript, lint, 10 UX + 54 функционални React + 9 SEO + 5 release проверки (**78 общо**), production build, 276 публични HTML страници и 269 Markdown версии. Проверяват се частните данни при изход, файловите заглавки, възстановяване и повторен запис на черновата, смяна на град, отложени ресурси, CSP във всички HTML, отказ на секретен ключ преди build output, снимки/кредити и действителен lastmod. Изображенията и backend транспортът в React тестовете са изолирани заместители; няма реално изпратен SMS, OAuth вход, чуждо съобщение или контактна форма.

След merge: **Readdy Pull от main → Publish**. GitHub Actions не публикува домейна. Хостингът трябва да отдава генерирания `out`, включително статичните градски HTML преди SPA fallback. След Publish се проверяват реалният вход, снимки, CSP в браузъра и production производителността.

Meta CSP не задава HSTS, X-Content-Type-Options, frame-ancestors или Permissions-Policy. Те изискват реални HTTP response headers от хостинга и не са приложени или удостоверени в тази промяна. Настройката трябва да се изпълни при доставчика и да се провери на публикувания домейн; frame-ancestors се задава в HTTP CSP. Няма обещание за нулев риск, приключен penetration test или enterprise SLA.
